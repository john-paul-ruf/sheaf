Implementation contract

Choice → verification → recovery

MOD-020 has no preselected choice. Reuse asks for this device’s local unlock passphrase again; it never retrieves a retained secret. A different secret has a named-vault field and confirmation. Issue a separate vault code in both paths. In the reuse path, present the existing local code alongside the new vault code, each labelled. Only “I saved this code” / “I saved both codes” acknowledges issuance. Printing does not acknowledge it.

Unlock and re-view have different jobs

MOD-023 opens the named home. A connected second home asks once; its key is then held in the encrypted local store and is not re-entered at launch. A bundle asks at open time. Re-view starts from Recovery codes while local store and named vault are unlocked, asks for the named vault’s passphrase, then reveals that vault’s code. It is not MOD-022, which asks for the local passphrase and reveals only the local code.

Error and cancellation

Wrong-secret errors name the attempted scope, clear the secret draft, set aria-invalid and describe the field error. Operation errors use a separate alert; they do not claim a wrong secret. Nothing assigns a home or advances a backup fact on error or cancellation. Retry uses the same scoped form. Cancel/Escape dismisses without acknowledgment and returns to the caller. After code issuance, dismissal must not masquerade as acknowledgment or imply rollback of a created vault; re-view remains the approved way to see an existing code. No timeout or attempt policy is introduced here.

Keyboard, focus and layout

Native modal focus containment; initial focus on the title, then DOM order through choices/fields, show/hide and actions. Radio keys use native arrow navigation. Enter submits only an enabled form. On field error, focus the invalid field; on an operation error, focus the alert. Escape equals Cancel/Close, backdrop clicks do nothing, and close restores the exact launcher. Show/hide preserves focus. Empty forms disable primary actions; checking announces status and prevents duplicate submission. At 320/430px use a scrollable bottom sheet with stacked actions; paired codes use a full-height sheet. At 600px+ retain a single-column 480px dialog. Shell changes at 900/1200px; safety surfaces remain shell-owned in every app theme.
